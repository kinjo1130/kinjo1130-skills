# UAT Checklist Skill

## Purpose

指定された **1 件の PR**(または現在のブランチの基準ブランチとの差分) から、**人間 QA / [uat-record](../uat-record/SKILL.md) skill** が消化する動作確認チェックリストを生成する。

情報発生時点 (実装直後、diff のコンテキストを最も持っている時) でチェックリストを作り、そのまま同一セッションで uat-record に消化させるのが正規フロー。

## 責務範囲(厳守)

- **このスキルが行うこと**: 1 件の PR (またはブランチ差分) の diff を解析し、確認項目テーブルを `<out>/checklist.md` に書き出すまで。`--comment` 指定時は PR コメントへの冪等投稿まで
- **このスキルが行わないこと**: 確認の実行 / ブラウザ操作 / 複数 PR の集計 / 判定。それらは uat-record の責務

## You Must Read

- プロジェクトのルーティング定義 (routes 定数ファイル、`app/` ディレクトリ構成など)。対象画面列に書く URL パスはここから導出し、**捏造しない**
- 対象 PR の `gh pr view --json` メタデータと `gh pr diff` の実差分 (ブランチモードでは `git diff origin/<base>...HEAD`)
- 必要なら PR の linked issue (`gh pr view <num> --json closingIssuesReferences`)

## 引数仕様

```
/uat-checklist [--out <dir>] [--comment] ["<PR番号>"]
```

### 位置引数: PR 番号(任意、最大 1 個)

`#` プレフィックスは省略可。**省略時はブランチモード**: 現在のブランチと基準ブランチ (リポジトリの default branch。開発フローで develop 等を使っている場合はそれ) の差分 `git diff origin/<base>...HEAD` を対象にする。2 個以上抽出できた場合は即時 throw。

### `--out <dir>`(任意)

- **デフォルト**: PR モードは `.dev/uat/pr-<PR番号>`、ブランチモードは `.dev/uat/branch-<ブランチ名の / を - に置換したもの>`
- 出力ファイル名は **必ず `checklist.md`** に固定する (uat-record がパス決め打ちで読むため)
- 既存ファイルがあれば**上書きしてよい** (PR 更新に伴う再生成が正規フロー)

### `--comment <PR番号>`(任意)

**既存の checklist.md を再生成せずそのまま** PR コメントへマーカー `<!-- uat-checklist v1 -->` 付きで冪等投稿する (既存マーカーコメントがあれば `gh api -X PATCH` で更新、無ければ `gh pr comment`)。PR 番号は投稿先の指定であって ID の付け直しではない (uat-record の report と ID の対応を保つため)。checklist.md が存在しなければ throw。

## 基本姿勢

- **diff から導ける事実だけを書く。** 期待結果が diff / PR description / linked issue から確定できない場合は「不明」と書く (uat-record 側で skipped になる)。もっともらしい期待結果を捏造しない
- **人間 QA が読む成果物。** 操作・期待結果はそのプロダクトの業務語彙で書く。ただし URL パス・ボタン名などの操作手順は正確性優先で技術表記可
- **UI・画面挙動に影響しない変更は「確認項目なし」と明示する。** 空テーブルやファイル未生成で表現しない (未生成と区別がつかなくなる)
- **バックエンド変更も画面に翻訳する。** API / DB / バッチの変更は「どの画面のどの挙動に影響するか」に翻訳して項目化する。翻訳できない純内部変更 (CI 設定・挙動不変のリファクタ等) は確認項目なし

## 優先度定義

| 優先度 | 基準 |
|---|---|
| P0 | 課金・認証・認可・データ削除/破壊系。間違うと取り返しがつかないもの |
| P1 | 新機能の主要フロー、既存機能の動作変更 |
| P2 | レスポンシブ、エッジ条件、空/エラー/ローディング状態 |
| P3 | 見た目の微調整 |

## 手順

fail-fast を徹底する (不明な状態をサイレントスキップしない)。

### Step 1: 前提確認

PR モード (または `--comment`) で `gh` CLI が未認証なら即時 throw。

### Step 2: モード判定と対象特定

- 位置引数から数値を抽出。1 個 → PR モード。0 個 → ブランチモード。2 個以上 → throw
- ブランチモードで現在のブランチが基準ブランチそのもの (main / develop 等) なら throw (差分の基準が成立しない)

### Step 3: 差分取得

- PR モード: `gh pr view` でメタデータ (`number,title,body,files,baseRefName,url`)、`gh pr diff` で差分。`gh` が 4xx/5xx なら throw
- ブランチモード: `git fetch origin <base>` 後に `git diff origin/<base>...HEAD` と `git diff origin/<base>...HEAD --name-only`
- diff は 800 行で truncate。truncate 時は `[TRUNCATED: 全 N 行中 800 行まで]` を付けて分析に渡し、**truncate された範囲は `--name-only` のファイル一覧から項目を推定**する (ファイル名すら見ないまま「確認項目なし」にしない)

### Step 4: 変更の性質分類と影響画面の特定

変更ファイルと diff 内容から変更の性質 (見た目 / データ取得 / フォーム入力 / 認証・認可 / データ破壊系 / 非同期処理 / 純内部) を分類し、影響する画面 URL をルーティング定義から特定する。共通コンポーネントの変更は利用箇所を grep して影響画面を広めに取る。

### Step 5: 確認項目の組み立て

変更の性質に応じた項目を作る。目安:

- 見た目変更 → 対象画面の表示確認 (P1 or P3) + 主要ブレークポイント (P2)
- データ取得変更 → 正常表示 (P1) + ローディング / エラー / 0 件 (P2)
- フォーム変更 → 主要入力フロー (P1) + バリデーションエラー表示 (P2)
- 認証・認可・削除系 → 該当操作の成否 + 権限外アクセスの拒否 (P0)
- 非同期処理 (ジョブ・バッチ) → ジョブ起点の画面で開始〜結果反映 (P1)

項目数の目安は 1 PR あたり 3〜10 件。P0 相当が無い PR に無理に P0 を作らない。

### Step 6: 出力ファイル生成

`<out>/checklist.md` に「出力形式」を厳守して書き出す。完了後、最終応答の末尾に `OUTPUT: <絶対パス>` の 1 行を置く。

### Step 7: PR コメント投稿(`--comment` 時のみ)

マーカー `<!-- uat-checklist v1 -->` で冪等投稿する。

## 出力形式(checklist.md)

uat-record が機械可読にパースする**唯一の契約**。厳守する。

```md
<!-- uat-checklist v1 -->

## UAT チェックリスト: #<PR番号> <PRタイトル>

| ID | 対象画面 | 操作 | 期待結果 | 優先度 | 外部送信リスク | 由来PR |
|---|---|---|---|---|---|---|
| C-<PR番号>-01 | /projects | 一覧を開く | フィルタが表示され、選択すると一覧が絞り込まれる | P1 | no | #10 |
| C-<PR番号>-02 | /projects | フィルタ選択中にデータ 0 件の条件を選ぶ | 空状態メッセージが表示される (エラーにならない) | P2 | no | #10 |
```

- 1 項目 1 行の Markdown テーブル。列順は固定 (ID / 対象画面 / 操作 / 期待結果 / 優先度 / 外部送信リスク / 由来PR)
- ID はブランチモードでは `C-<ブランチ名の / を - に置換>-01` 形式の連番。**PR 作成後もこの ID を維持する** (ID を変えると uat-record の report と対応が取れなくなる)
- 由来PR 列はブランチモードでは `-` (ハイフン 1 文字)。PR モードで生成した場合のみ PR 番号
- 対象画面はルーティング定義由来の URL パス (動的セグメントは `[id]` 表記のまま)
- 期待結果を確定できない場合は「不明」とだけ書く
- 外部送信リスク: メール / SMS / 決済 / 外部 LLM の大量呼び出しを伴う操作なら `yes`、それ以外 `no`
- テーブルの後に補足 (前提 seed、確認順の推奨など) を自由記述してよい。ただし**テーブルより前には何も挟まない** (マーカー → 見出し → テーブルの順)
- 確認項目が無い場合はテーブルの代わりに `**確認項目なし**(理由: <1 行>)` を書く

## fail-fast チェックリスト

| 条件 | 挙動 |
|---|---|
| PR モードで gh CLI 未認証 | throw |
| PR 番号抽出が 2 個以上 | throw |
| ブランチモードで現ブランチが基準ブランチ | throw |
| `gh pr view` が 4xx/5xx | throw (リトライしない) |
| `--comment` かつブランチモード | throw |
| 生成結果が空 (テーブルも「確認項目なし」も無い) | throw |

## uat-record との棲み分け

| スキル | 責務 |
|---|---|
| **uat-checklist**(本スキル) | 何を確認すべきかの列挙 (checklist 生成) |
| [uat-record](../uat-record/SKILL.md) | checklist の Playwright MCP 消化 + 判定 + 動画・スクショ |
