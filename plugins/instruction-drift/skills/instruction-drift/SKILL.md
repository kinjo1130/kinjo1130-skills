# 指示文書とコードの食い違いを直す

AIエージェントは、指示文書の記述が今のコードと食い違うと、食い違いに気付いていても指示文書に従う。このskillは、食い違いを指示文書の側で解消し、残った食い違いにエージェントが流されないようにする。

判断の基準は、今のコードが実際にどう書かれているかである。このskillはコードを書き換えない。指示文書に合わせてコードを直すと、動いていた既存のコードが壊れる。

## 1. 対象の文書を集める

リポジトリの中で、AIエージェントに指示として渡る文書をすべて対象にする。ルートと下位ディレクトリの CLAUDE.md・AGENTS.md、それらが import や参照で読み込ませる文書、ツールごとの rule や skill の文書がこれに当たる。

呼び出し元が範囲を指定した場合は、それに従う。

## 2. 記述を、コードで確かめられる主張に分ける

文書の記述のうち、リポジトリの今の状態について述べている物を抜き出す。ファイルやディレクトリの配置、コマンドとスクリプト、依存ライブラリとそのversion、命名、コードの書き方の規則、テストの書き方、環境変数がこれに当たる。

人の運用手順やレビューの方針のように、コードを読んでも正否が決まらない記述は対象にしない。

## 3. コードと照らし合わせる

主張ごとに、コードの実態を確かめる。

- 書き方の規則は、1箇所の例外で判断しない。複数の箇所と、最近の変更でどう書かれているかを見て、今の慣習を決める
- コマンドは、定義があるかで確かめる。副作用のあるコマンドは実行しない

食い違いを、次の2つに分ける。

- 文書が古い: 参照先が存在しない、コマンドの定義が無い、コードが一貫して別の書き方をしている。文書を直す対象にする
- どちらが正か決められない: コードの中で書き方が混在している、文書の規則への移行が途中に見える、文書が意図して禁じている事にコードが違反している。文書もコードも変えず、判断材料と共に報告する

## 4. 文書を直す

「文書が古い」に分けた食い違いだけを直す。

- 記述を今のコードに合わせて書き換える。存在しなくなった物の記述は消す
- 最初からそう書かれていたかのように書く。「以前は〜だった」のような経緯を文書に残さない
- 直した記述が、同じ文書の他の記述や、他の指示文書と矛盾しないかを確かめる

エージェントが必ず読む入口の指示文書に、次の一文が無ければ足す。CLAUDE.md が AGENTS.md を読み込ませているように、入口が1つにまとまっている場合は、その1つに足せば足りる。

```
When a repository's documentation and its existing code disagree, follow the conventions used in the existing code, and in your final reply point out each inconsistency you found.
```

## 5. 報告する

呼び出し元が報告先を指定した場合は、それに従う。指定が無ければ、最後の返答で報告する。食い違いが無ければ、無かった事と、対象にした文書の一覧だけを報告する。

報告の形式は次の例に倣う。根拠には、コードの実態を確かめたファイルのパスを書く。

```markdown
## 直した食い違い

- `AGENTS.md:12` テストは `pnpm test:unit` で実行すると書かれていたが、`package.json` に `test:unit` の定義が無く、`test` が vitest を実行している。`pnpm test` に直した
  - 根拠: `package.json`

## 判断が要る食い違い

- `.claude/rules/api.md:8` エラーは Result 型で返すと書かれているが、`apps/api/src/routes/` の 14 ファイル中 9 ファイルが例外を投げている。最近の変更 3 件はどちらも含む
  - 選択肢: 文書を例外に合わせる / コードを Result 型へ移行する
  - 根拠: `apps/api/src/routes/users.ts`, `apps/api/src/routes/orders.ts`

## 対象にした文書

- `AGENTS.md`
- `.claude/rules/api.md`
```

## CI に組み込む

定期精査を CI に組み込むよう頼まれた場合は、`templates/instruction-drift.yml` を対象リポジトリの `.github/workflows/` に置く。このworkflowは週に1回このskillを実行し、直した食い違いを pull request に、判断が要る食い違いだけの場合は issue にまとめる。

置いた後、ユーザーに次の準備を伝える。

- リポジトリに Claude の GitHub App を入れ、認証情報を secret に登録する。template は `CLAUDE_CODE_OAUTH_TOKEN` を読む。API key を使う場合は `anthropic_api_key` に差し替える
- 実行の曜日と時刻は `cron` で変えられる。cron は UTC で書く
